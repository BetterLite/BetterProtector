# BetterProtector v1.1.0

**Release date:** October 30, 2026

This release focuses on full CommandoX integration, Bedrock tab-completion support, and a
comprehensive bug-fix pass across the entire codebase.

---

## 🐛 Bug Fixes
- **PacketHooker crash (`Undefined array key 0`)** — `DataPacketSendEvent::getTargets()` returns
  a non-sequentially keyed array; replaced `$targets[0]` with a safe `array_values(...)[0] ?? null`
  and an early-exit when empty.
- **PacketHooker data loss** — the packet is now reassembled with the original
  `unusedHardEnums` and `unusedSoftEnums`, so other plugins' commands and soft enums
  (e.g. MultiWorld) are no longer destroyed.
- **PacketHooker crash safety** — disassemble/assemble is wrapped in `try/catch`; on any failure
  the original packet is sent untouched and the error is logged.
- **Players trapped inside no-enter areas** — `onMove` performed the `canEnter` check on *every*
  movement, freezing players already inside an `enter: false` area. Entry is now only enforced when
  actually transitioning between areas (`$fromArea !== $toArea`).
- **Dead `onCommand()` removed** from `BetterProtector` — the command is registered through the
  `CommandMap`, so the method was never invoked. Unused imports cleaned up.
- **Pos1/Pos2 partial coordinates** — `/area pos1 100` silently fell back to the player's position.
  All three coordinates (x y z) or none are now required, with a clear error message.
- **Priority bounds check** — `/area priority` now accepts only `-1000000 … 1000000`
  (argument-level validation plus a defensive runtime check).
- **Flag value enum completed** — the value argument now accepts all 14 values recognized by
  `Flag::parseValue()`: `allow, deny, true, false, on, off, enable, disable, enabled, disabled,
  yes, no, 1, 0`.
- **Stale singleton after disable** — `BetterProtector::$instance` is now nullable and cleared in
  `onDisable()`; `getInstance()` throws a clear runtime exception if the plugin is not enabled.
- **Tab-completion survives `/reload`** — `PacketHooker::unregister()` resets the static
  registration flag on disable so the listener is re-registered on the next enable.
- **Dead code removed** — unreachable `delete`/`del` switch cases in `WhitelistSubCommand` and
  unreachable `entry`/`exit` cases in `MsgSubCommand`.
- **`AreaCommand::onRun()`** — now uses the public `getSubCommands()` getter instead of directly
  accessing the protected `$subCommandsByName` property.
- **Redundant `getAreaAt($to)` call** removed from `onMove` (result is now computed once).
